# 智账首页视觉基准（Step 1）

> 本文只记录视觉基准和估算值，不代表已经完成页面改造。
> 产品原稿是唯一视觉真源；当前页面功能、路由、数据、Pinia、localStorage 和 AI 逻辑均不因此文件改变。

## 基准尺寸

- 产品原稿截图：`961 × 1637`
- 原稿宽高比：`961 / 1637 ≈ 0.587`
- 主要开发视口：`390 × 844`
- 原稿按 390px 宽度等比换算后的内容高度：约 `664px`
- 结论：390×844 的视口中约有 180px 属于额外背景/安全区域，不应把原稿插画强行拉伸到 844px 高。

## 原稿与当前实现的主要差异（估算）

| 区域 | 原稿方向 | 当前实现 | Step 1 基准结论 |
|---|---|---|---|
| 页面比例 | 竖长完整构图 | `min-h-[100dvh]` 加固定底部导航 | 以 390×844 为视口，但保留原稿内容比例 |
| 顶部区域 | 标题与头像紧凑，标题占比大 | `Home.vue` 顶部使用普通 flex 布局 | 保留结构，重新建立高度和间距 token |
| 标题 | 深棕手写感大标题 + 不规则刷色 | 系统字体 + 规则 PNG 刷色 | 字体和刷色素材后续需要替换 |
| 小黄鸡头像 | 大圆徽章、蛋壳小黄鸡 | `chick-avatar.png` 圆框头像 | 素材方向可保留，尺寸需校准 |
| 日历位置 | 页面中上部，卡片占主体 | 当前位于标题下方 | 先固定卡片顶部和宽度基准 |
| 日历宽高 | 宽度约占原稿宽度 90% | 当前接近 90% | 比例方向基本一致，高度需要重测 |
| 日历夹子 | 两个厚实夹子，超出卡片顶部 | 当前是 CSS 小胶囊 | 应优先使用或重做透明夹子 PNG |
| 日期网格 | 日期格子横向矩形，约 1.5:1 | 当前使用 `aspect-square` | 后续必须改为横向比例 |
| 月度收支 | 日历卡片底部，左右两块 | 当前逻辑正确，视觉比例偏小 | 数据逻辑保留，视觉布局重做 |
| 底部插画 | 猫、熊、植物、叶片构成完整场景 | 当前是固定小图排布 | 后续单独建立底部场景层 |
| 底部黄色区域 | 大面积不规则黄色波浪 | CSS 渐变 + 椭圆伪元素 | 最好使用完整透明素材，CSS 作为兜底 |
| 底部导航 | 四个较大图标，中央按钮突出 | 当前四个图标加 `h-24` 加号容器 | 路由和激活逻辑保留，视觉重做 |
| 中央 + 按钮 | 大圆盘，超过导航上沿 | 当前光晕素材有透明边 | 按可见圆盘直径校准，不按素材容器大小判断 |
| 安全区域 | 黄色背景延伸到页面底部 | 当前使用 `env(safe-area-inset-bottom)` | 保留安全区逻辑，背景需要覆盖到其后面 |

## 统一 token 文件

实际变量定义在：

`frontend/src/styles/home-visual-tokens.css`

Step 1 只新增变量并在 `style.css` 中导入，不让页面立即使用这些变量，因此页面外观和功能暂时不变。

## 后续实施提醒

- 不要把整张原稿截图直接当页面背景。
- 日期、金额和按钮继续使用真实 DOM，不能变成不可点击的图片。
- 后续需要优先补齐透明 PNG：日历外框、夹子、底部波浪、猫、熊、植物、导航和中央按钮。
- 所有估算值应在 Step 3～Step 6 用原稿重新对齐。
